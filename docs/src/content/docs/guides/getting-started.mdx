<Aside type="caution">
  Packages currently go to a **test** channel,
  `https://prefix.dev/veckothegecko/qgis-stack-test`. The final channel URL will
  be different.
</Aside>

<Steps>

1. [Install pixi](https://pixi.sh/latest/installation/).

2. Create a workspace and list QGIS and the plugins you want:

   ```toml title="pixi.toml"
   [workspace]
   name = "my-gis"
   # QGIS Stack first, then conda-forge for QGIS and the plugins' dependencies.
   channels = ["https://prefix.dev/veckothegecko/qgis-stack-test", "conda-forge"]
   # QGIS 4.2 on conda-forge needs macOS 14 or later.
   platforms = [
     { name = "osx-arm64-14", platform = "osx-arm64", macos = "14.0" },
     "linux-64",
   ]

   [dependencies]
   qgis = ">=4.2,<5"
   qgis-stack-quickosm = "*"
   qgis-stack-dataplotly = "*"

   [tasks]
   # A profile inside the workspace, so plugins installed through QGIS's
   # Plugin Manager in your usual profile don't override these.
   qgis = "qgis --profiles-path $PIXI_PROJECT_ROOT/.qgis"
   ```

3. Start QGIS:

   ```sh
   pixi run qgis
   ```

   The plugins are installed. Turn them on in **Plugins → Manage and Install
   Plugins → Installed**, or have them start enabled: see
   [Enabling plugins](/guides/enabling-plugins/).

</Steps>

## Package names

A plugin's package is `qgis-stack-` plus its slug on plugins.qgis.org in
lower case: `QuickOSM` → `qgis-stack-quickosm`, `quick_map_services` →
`qgis-stack-quick_map_services`. Underscores and dashes are kept as they are.
The [catalogue](/catalogue/) lists every package.

## Which QGIS versions

Each package depends on the QGIS range in the plugin's `metadata.txt`, padded
the way QGIS's Plugin Manager pads it: `qgisMinimumVersion=3.40` and
`qgisMaximumVersion=4.99` become `qgis >=3.40.0,<=4.99.99`. pixi therefore
won't install a plugin into a QGIS that would refuse to load it.

conda-forge builds QGIS 3.40, 3.42 (Linux only), 3.44 and 4.2, but not 4.0.
Packages are tested on the
oldest of those inside the plugin's range and on the newest QGIS.

## Platforms

Packages are `noarch`, so the same package works on Linux and macOS. Windows
isn't supported yet: QGIS looks for system plugins under `Library\` there, which
needs a separate variant (planned).
